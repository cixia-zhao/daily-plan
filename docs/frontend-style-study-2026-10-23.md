# 全站风格与响应式计时面板：讨论稿

日期：2026-10-23。状态：用户已回复“按你的推荐来”，确认手机底部抽屉／迷你条、桌面右侧、历史统一复盘。真实实现、隔离验证及预览已经完成；下方调研描述按其时点理解，最新规则见DESIGN.md。

## 用户明确要求

- 课程点“开始”后只显示细分选项；确认具体细分或“暂不细分”后，才打开计时与记录。请求失败保留选项并明确反馈，不提前展示运行态。
- 删除执行页“正在查看”整行和日期控件，任务／细分在状态区同一行。长文本优先省略细分，完整信息仍可访问，不能挤走停止。
- 执行页分“课程”和“完成与复盘”页签，后者容纳原完成情况、习惯状态和进入复盘，不在课程下重复堆放。
- 统一今天、执行、日／周复盘、设置、GPT工作台的导航、按钮、表单、容器与页签反馈。保留已认可的内容布局与业务数据，不将统一风格等同于把每页改成同样的大卡片。
- 手机优先探索底部抽屉，桌面形式待共同决定；恢复暖纸书刊风格的视觉层次，避免过浅、过空。

## 实际问题与原因

只读截图核对五页；拦截浏览器所有非GET接口请求，没有写入预览库，页面无脚本错误。

| 范围 | 现状 | 调整方向 |
| --- | --- | --- |
| 今天 | 顶部保留品牌，导航13px、8px圆角及浅陶土选中背景 | 所有页面共用同一响应式外壳 |
| 执行／复盘 | 手机隐藏品牌，导航14px、无圆角、陶土下划线 | 同一断点下保持导航尺寸、位置与选中表达一致 |
| 设置／工作台 | 仍沿用原品牌导航与圆角样式，设置多层容器 | 共用外壳、输入与分组规则，去掉重复外框 |
| 状态文本 | workspace.css强制当前任务与细分各占整行 | 单行任务／细分，停止独立不被压缩 |
| 顶部主导航 | 三项本来都用普通链接换页；不同样式造成额外跳动 | 保留路由、后退与草稿语义，统一页面过渡 |
| 页内页签 | 复盘数据／收尾已有位移动效，今天安排等无共同机制 | 抽出统一页签样式、指示条及方向动效 |
| 计时面板 | 当前直接插入页面，容器边界和层次过弱 | 纸色页面、深一阶分区底、浅色操作面板与重点计时区 |

参考代码：app/templates/base.html、execute.html，app/static/style.css、today.css、workspace.css、app.js及review.js。此阶段仅检查，未改动这些文件。

## 调研依据与设计判断

- [Material底部面板](https://m1.material.io/components/bottom-sheets.html)：区分持续面板和带遮罩的面板；持续控制可在主任务旁保留，大屏可改用其他表面。手机抽屉不应默认强占整个屏幕。
- [Material官方底部面板组件说明](https://raw.githubusercontent.com/material-components/material-components-android/master/docs/components/BottomSheet.md)与[侧边面板说明](https://raw.githubusercontent.com/material-components/material-components-android/master/docs/components/SideSheet.md)：标准面板能与主内容共存，模态面板强调当前任务。推荐桌面右侧非模态，课程仍可直接点击；居中模态作为对照，关闭后再切课。
- [shadcn响应式抽屉示例](https://ui.shadcn.com/docs/components/radix/drawer#responsive-dialog)：手机抽屉与桌面对话框可以共用内容、分别适配外壳。仅借鉴交互模式，无安装React或新运行库的计划。
- [Material导航过渡](https://m1.material.io/patterns/navigational-transitions.html)及[Chrome多页面过渡说明](https://developer.chrome.com/docs/web-platform/view-transitions/cross-document)：同级内容以方向表达关系；当前多页面架构可渐进增强过渡，无需为了动效改成单页应用。浏览器不支持时保留正常导航与简短进入反馈，不阻止操作。
- [Claude Code官网](https://claude.com/product/claude-code)：作为用户指定的书刊气质参考。具体纸色、对比、字号和容器由本项目统一定义，不复制其产品功能与布局。
- Material 2部分页面仅返回JavaScript占位，没有当作已完整读到正文；使用可访问的官方旧版规范和官方组件源码补足交互依据。示例中的时间与数据仅为讨论，不冒充实际统计。

## 推荐方案

### 统一风格

暖纸背景配浅色操作面、较深的暖灰分区底；正文炭黑，说明暖灰，陶土只用于当前选择、进度与少数强调。项目色继续为低饱和暖色且与文字／图标共用识别。圆角按容器层级统一，阴影仅用于浮起的抽屉、菜单和面板；普通内容通过对比、留白、细线分组，避免处处堆卡片。保留正常正文和至少44px常用触控区。

手机所有页面统一为今天／执行／复盘／更多的导航；桌面统一左品牌、右导航。今天的清单、复盘图表和设置分组的内容职责保持。主导航与页内页签共用约220～260ms的短移动和透明度过渡，指示条连续移动；具体数值是本项目拟定值。抽屉从底部、侧板从右侧打开，关闭可更快；减少动态效果时取消位移。重复选择不重播，快速连续切换不排队。

### 计时与记录

- 手机：底部抽屉，首开高度按内容约半屏至三分之二屏，上方保留课程上下文；长记录在面板内滚动，计时与停止仍易访问。展开时轻遮罩增加层次，收起后运行不中断，推荐底部迷你条保留任务／细分、计时、停止；空闲收起则回悬浮入口。背景是否可直接操作仍可按用户偏好讨论。
- 桌面推荐：约360～420px的右侧非模态面板，课程区随可用空间让位。面板按内容收紧，不强行拉满高度；无空面板占位。窄窗口退回抽屉；不能只按触屏设备名称判断。
- 桌面对照：约420px的居中浮层，有遮罩、内容聚焦，但课程需要先关闭浮层才能操作。适合偶尔编辑，对频繁切课便利性较弱。
- 面板内容顺序一致：标题／收起、任务／细分单行、明确计时与停止、今日目标进度、可编辑时间轴、快捷操作。名称和控制保持稳定位置；短段不硬塞文字，已有两次点击编辑规则保持。
- 编辑窗、快捷补记与选择标签的层级需明确。手机避免两个满高抽屉叠放；编辑时仍保留上下文，返回恢复时间轴选择与位置。保存中不能误关闭／换日，失败保留输入。

### 日期与历史

执行页删除日期入口是明确要求。尚需决定历史工作范围：推荐执行只负责今天，历史日期／补录／编辑统一在复盘日期下进入记录面板；另一方案保留从复盘进入历史执行页，但不再给执行页切日入口。旧链接的跳转和活动段提示应随选择处理，不能只删显示却留下易误操作的隐含历史状态。

## 样稿与验证

会话内交互样稿提供手机底部抽屉、桌面右侧面板、桌面居中浮层三种视图，也能切今天／执行／复盘／设置、执行完成页签及复盘内部页签。示例保留44px按钮、暖纸层次和任务／细分同排。样稿不连接真实接口，不写入数据，不表示全部业务已实现。

本机浏览器已验证三种面板显示、选细分前不展开／选完才打开、收起迷你条与停止、完成页签、导航及复盘切换、手机宽度无横向溢出，未发现脚本错误；截图已实读。正式页面未修改，应用回归需在方案确认后的实现阶段重新执行。移动端拖动惯性、软键盘、系统返回与Safari仍需实际实现后验收。

## 待共同决定

1. 桌面右侧面板（推荐）或居中浮层。
2. 手机运行收起后用底部迷你条（推荐）或保留顶部紧凑计时。
3. 执行只管今天、历史统一从复盘处理（推荐），或继续允许从复盘进入历史执行页且无切日控件。


## 实现落地补充

已按推荐实施全站样式、页签、面板及历史入口。主导航采用共用进入动效和指示条，保留原生路由；实验中原生跨文档过渡在受控时钟／状态中断时产生异常，最终不依赖它。240ms和180ms是本项目选定值，并非引用规范的硬性数字。手机常用触控与今天页一屏预算已回归，历史编辑与复盘草稿联动已检查；具体结果见HANDOFF.md顶部。
