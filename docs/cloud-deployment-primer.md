# 云端部署小白说明

这份文档不是技术手册。  
它是给你这种“现在只想知道大概是什么、为什么要这么做”的版本。

目标只有一个：

- 帮你听懂我们后面聊云端部署时常出现的那些词
- 帮你分清“哪些东西是为了更好用”“哪些东西是为了不丢数据”“哪些东西只是技术实现细节”

## 先说结论

你现在最不舒服的地方，不是项目本身不好，而是**它现在主要靠手机本地 Termux 挂着跑**。

这会带来几个直接问题：

- 手机上必须让它活着
- 用起来不够顺手
- 数据更容易因为本地环境折腾、误操作、换设备而丢掉

所以我们现在考虑“上云”，本质上不是为了炫技，而是为了这三件事：

1. 让项目一直在服务器上稳定运行
2. 让你手机打开就能用，不再依赖本地 Termux 小窗
3. 让数据备份更稳，别再轻易丢

---

## 这些词分别是什么意思

### 1. 云服务器

可以把它理解成：  
**一台长期开机、放在远处机房里的电脑。**

它和你手机/电脑最大的区别是：

- 你不需要让自己手机一直挂着它
- 它可以 24 小时开机
- 你可以随时从别的设备连过去用

对你这个项目来说，它的意义就是：

- 不再靠手机本地跑后端
- 后端改成在阿里云上长期运行

---

### 2. SQLite

可以把它理解成：  
**项目现在用来存数据的一个本地数据库文件。**

对你最重要的理解是：

- 它不是“很多数据库服务里那种复杂的大系统”
- 你这个项目现在的数据，本质上主要就是一个文件

所以：

- 好处是简单，适合你这个单用户小项目
- 风险是如果这个文件丢了、坏了、被覆盖了，数据就容易一起没

你之前丢数据，核心痛点就和这个有关。  
不是 SQLite 本身一定不行，而是**没有把“备份这个数据文件”当成一个正式动作去做**。

---

### 3. 自动备份

自动备份的意思很简单：

- 服务器每天自动把那份数据库文件复制出一份
- 不只保留最新的一份，而是保留最近几天的历史版本

它解决的问题是：

- 你今天误删了数据，还有昨天的备份
- 项目出问题了，还能回退
- 服务器坏了，也不至于完全没有恢复手段

你可以把它理解成：

> 每天自动帮你留一个“后悔药”

---

### 4. 手动导出备份

这个和自动备份不同。

自动备份是：

- 服务器自己定时做

手动导出是：

- 你在项目里点一下
- 把当前的一份备份文件下载到你自己电脑或手机

它的意义是：

- 你手里也有一份
- 不完全依赖服务器
- 真出问题时，恢复会更安心

所以我们后面才会说：

- 自动备份是“后台保险”
- 手动导出是“自己手上也留底”

---

### 5. `systemd`

这个词你可以简单理解成：

**Linux 服务器里的“后台应用管理员”。**

它做的事包括：

- 开机自动把你的项目启动起来
- 如果项目意外崩了，帮你重启
- 让你能查它现在是不是在运行
- 让你能看错误日志

为什么要它：

因为我们不想让你的项目变成这种状态：

- 你每次都要手动进服务器敲命令启动
- 一断就没人管

所以 `systemd` 的作用不是“高级”，而是：

> 让你的项目像一个正式长期运行的服务，而不是一个临时手工启动的程序

---

### 6. Docker

`Docker` 你可以先把它理解成：

**一种把项目打包成“标准运行盒子”的方式。**

它的好处通常是：

- 换机器更方便
- 环境更整齐
- 部署更标准化

但对你现在这个阶段来说，`Docker` 不是最重要的。

因为你当前最需要先解决的是：

- 能不能稳定跑
- 手机能不能顺手用
- 数据能不能别再丢

所以你可以先把它看成：

- 不是必须马上上的东西
- 更像后面“做得更标准”时才可能考虑的工具

也就是说：

> `Docker` 不是现在的目标，只是可能的实现手段之一

---

### 7. 反向代理

这个词听起来很绕，你可以先理解成：

**一个放在项目前面的“门卫”或者“转发层”。**

它常见用途有：

- 帮你转发访问
- 做更正规的 HTTPS
- 加一层访问保护
- 隐藏真正的后端端口

对你现在来说，不需要先深入理解。  
你只需要知道：

- 如果以后做公网访问，它很常见
- 但你当前更可能先走“私有访问”，那它不是第一优先级

---

### 8. 私有访问 / Tailscale

你可以把它理解成：

**让你的手机和服务器之间拉一条“只有你自己用的私有通道”。**

它和“公网直接裸露一个网址”最大的区别是：

- 不是谁都能扫到
- 更适合不买域名、不做备案的个人项目
- 安全性会比公网裸跑高很多

它会多出来的一点动作是：

- 服务器上装一个对应组件
- 手机上装一个轻量 App

但它不会像 Termux 那样：

- 在你手机本地持续跑整个后端
- 需要靠本地小窗保活应用本体

所以这两者不是一回事。

---

### 9. 健康检查

健康检查的意思可以理解成：

**专门留一个很简单的地址，用来判断项目是不是还活着。**

比如：

- 打开它，能返回“我还活着”
- 那就说明服务大概率正常

它不是给你平时使用的功能，主要是为了：

- 判断服务器上的项目有没有挂
- 后面排错更方便

---

## 代码备份 和 数据备份 不是一回事

这是最重要的一段。

### 代码备份

代码备份主要指：

- Git
- GitHub
- 提交代码

它保住的是：

- 你写的程序
- 文档
- 配置

### 数据备份

数据备份主要指：

- 你的每日计划
- 执行记录
- 单日复盘
- 周报
- GPT 留档

它们现在主要在数据库文件里。

所以：

- 你把代码推到 GitHub，不等于你的使用数据被备份了
- 你有 Git 提交，不等于你的复盘就安全了

这也是你之前“代码可能还在，但使用数据还是丢了”的根本原因。

所以后面我们才一直强调：

> Git 备份的是代码，不是你的真实使用记录  
> 真正要保的是数据库备份

---

## 为什么我们现在不优先做原生 App

不是因为原生 App 不好。

而是因为你当前最急的是：

- 先别再被 Termux 限制住
- 先让手机打开更顺
- 先把数据保住

如果现在直接冲原生 App，会马上引入更多事情：

- 新技术栈
- 新调试流程
- 新打包流程
- 新兼容问题

而你现有这个 Web 项目其实已经能用了。  
所以更合理的顺序是：

1. 先把现在这个项目迁到云上，稳定跑起来
2. 先把数据和访问体验稳住
3. 以后如果真的需要，再把它包成更像 App 的形态

也就是说：

> 现在先解决“能稳定长期使用”  
> 以后再解决“更像原生 App”

---

## 你现在真正需要关心的，不是所有技术词

你现在真正需要做决定的，其实只有这几个：

1. 你愿不愿意把主数据放到云服务器上  
   你已经说可以，而且更想要稳定备份

2. 你能不能接受“不是公网裸跑，而是走私有访问”  
   因为这样更适合你的个人项目现状

3. 你要不要把“自动备份 + 手动导出”一起做上  
   这样以后不容易再丢数据

剩下那些词，大多数只是“怎么把这件事做出来”的实现工具。

---

## 一句话版本

如果后面我再提这些词，你可以先这样理解：

- 云服务器：远处一直开机的电脑
- SQLite：你现在项目数据所在的那个文件
- 自动备份：每天自动留后悔药
- 手动导出：你自己手里也留一份
- `systemd`：服务器里的后台管理员
- `Docker`：把项目装进标准盒子的方法，但现在不是第一优先级
- 反向代理：项目前面的门卫
- Tailscale：你自己和服务器之间的私有通道
- 健康检查：看项目是不是还活着的简单入口
- Git 备份：保代码
- 数据库备份：保你的真实使用记录

如果你只记一句，那就是：

> 这次上云最重要的不是“技术酷不酷”，而是让项目别再依赖手机本地 Termux，顺便把你的真实数据保住。

## 怎么在 PowerShell 里进入你自己的服务器

这一段尽量写成“你以后自己也能照着做”的版本。

你可以把它理解成：

- PowerShell 是你电脑上的命令窗口
- `ssh` 是“从你电脑连到远处服务器”的命令
- 以后很多服务器操作，都是先用它连进去，再复制粘贴命令

---

### 1. 先打开 PowerShell

最简单的方法：

1. 在 Windows 开始菜单里搜索 `PowerShell`
2. 打开它
3. 看到一个可以输入命令的窗口就行

你不用先理解太多。  
把它先当成“给电脑下指令的窗口”。

---

### 2. 最基本的连接命令长什么样

最常见的形式是：

```powershell
ssh root@你的服务器公网IP
```

比如你的服务器如果公网 IP 是 `120.55.53.215`，那就是：

```powershell
ssh root@120.55.53.215
```

这里的意思分别是：

- `ssh`：发起远程连接
- `root`：要登录的服务器用户名
- `120.55.53.215`：服务器地址

---

### 3. 第一次连接时会看到什么

如果是第一次连这台服务器，PowerShell 可能会出现类似提示：

```text
The authenticity of host ... can't be established.
Are you sure you want to continue connecting (yes/no/[fingerprint])?
```

这时候输入：

```text
yes
```

然后回车。

这一步的意思不是出错，  
而是你的电脑第一次认识这台服务器，问你“要不要记住它”。

---

### 4. 如果现在是密码登录

接下来它通常会提示你输入密码：

```text
root@120.55.53.215's password:
```

这时候直接输入密码，然后回车。

注意：

- **输入密码时屏幕通常不会显示任何字符**
- 不会显示星号，也不会显示长度
- 这是正常现象，不代表没输入进去

如果密码对了，你会进入服务器，看到类似：

```bash
root@xxx:~#
```

这就说明你已经成功进入服务器了。

---

### 5. 以后最推荐的是“免密登录”

密码登录能用，但长期来看更推荐：

- 你的电脑保留一把“私钥”
- 服务器保存对应的“公钥”
- 之后你再执行 `ssh root@服务器IP` 时，就不用每次手输密码

这样做的好处是：

- 更方便
- 通常也更安全
- 后面我帮你部署、维护服务器时会更顺手

你前面提到的“把公钥加到服务器白名单里”，本质上就是在做这件事。

配置好之后，你以后常用的连接命令还是一样：

```powershell
ssh root@120.55.53.215
```

只是它会直接连进去，或者只在必要时让你输入密钥口令，而不是服务器密码。

---

### 6. 如果连接失败，最常见的是哪几种情况

#### 情况 A：`Permission denied`

常见意思是：

- 密码错了
- 服务器不让你这样登录
- 或者公钥还没正确加进去

它不一定表示“服务器坏了”，多数时候只是认证没通过。

#### 情况 B：`Connection timed out`

常见意思是：

- 服务器没开机
- 公网 IP 不对
- 安全组或防火墙没放行 SSH
- 网络临时不通

这更像是“根本没连到门口”。

#### 情况 C：`Connection refused`

常见意思是：

- 服务器是开着的
- 但 SSH 服务没正常监听

这时候通常要去阿里云网页控制台里排查。

---

### 7. 如果你还不会从 PowerShell 登录，先走网页控制台也完全可以

这个非常重要：

**不会 `ssh`，不等于你就不能管理服务器。**

你完全可以先用阿里云自带的网页远程终端：

- 进入阿里云 ECS 控制台
- 找到你的服务器
- 点“远程连接”或类似入口
- 先用网页黑窗口登录进去

这通常是新手最稳的第一步。

等你已经能在网页里正常登录、也看懂一点点基本操作后，  
再切回 PowerShell 用 `ssh`，会轻松很多。

所以你可以这样理解：

- 网页控制台：救急、首次配置、看得见入口
- PowerShell + `ssh`：以后日常维护更方便

---

### 8. 你以后最常用的，其实就这一个命令

```powershell
ssh root@你的服务器公网IP
```

如果你现在只先记住一个东西，就记住它。

因为以后很多步骤本质上都是：

1. 打开 PowerShell
2. 输入 `ssh root@你的服务器公网IP`
3. 进入服务器
4. 在里面继续执行别的命令

---

### 9. 一句话理解

以后如果我说“你先进服务器”，大多数时候意思就是：

> 在 PowerShell 里执行 `ssh root@你的服务器公网IP`，成功进入那个 `root@...` 的黑窗口

做到这一步，你就已经具备了最基本的服务器操作入口。
